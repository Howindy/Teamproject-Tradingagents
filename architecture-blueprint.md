## 1. Purpose

Two changes to the analysis pipeline:

- **FR-01 — Derived metrics service.** Growth rates, margins, trailing-twelve-
  month (TTM) totals, valuation multiples, liquidity ratios, and free cash flow
  are computed by deterministic code from SEC EDGAR filings, instead of by the
  model from raw statement tables.
- **CR-01 — Downstream context brief.** The five downstream debate agents read
  a bounded brief of each analyst report instead of the full report, which
  removes repeated evidence from every downstream prompt.

The two changes meet at the fundamentals report: FR-01 appends a
verified-metrics block to it, and CR-01 keeps that block verbatim in every
brief.

The software-engineering contribution is the boundary between model and code:
numeric derivation is moved behind a deterministic, independently verified
component, and model context is governed by an explicit, measured budget
policy instead of by habit.

## 2. Architectural drivers

### 2.1 Quality-attribute scenarios

| ID | Attribute | Source / stimulus | Environment | Response | Measure |
|---|---|---|---|---|---|
| QAS-1 | Correctness | Analyst needs latest-quarter year-over-year growth | Quarterly table without Q4 columns and with duplicate end dates | Value against the correct year-ago period, or `n/a` with reason | 0 wrong-period values on all fixtures (FR-01-AC1 to AC3) |
| QAS-2 | Cost | One analysis run | Baseline configuration (one ticker, 1 debate round, 1 risk round) | Downstream agents receive bounded briefs | Configured brief size and preservation checks (CR-01-AC1 to AC3); savings unmeasured |
| QAS-3 | Testability | Developer or CI checks FR-01 and CR-01 logic | No network, no model credentials | Deterministic tests on recorded baseline text | 9 of 11 criteria pure-function, 2 offline with mocks |
| QAS-4 | Robustness | Brief handling or metric input fails | Any run | Run continues with full report or `n/a` rows | 0 aborted runs caused by either feature (FR-01-AC7, blueprint §8) |
| QAS-5 | Traceability | Reviewer inspects a figure in the decision | Any run | Figure maps to inputs, period, and formula in the verified block | Every verified row has inputs and formula (DM-INV-07) |
| QAS-6 | Modifiability | Team adds a new derived metric | Development | Change limited to the metric catalog and calculator | No change outside `derived_metrics` and its tests |

### 2.2 Constraints

- SEC EDGAR is the only fundamentals source for derived metrics.
- No new `AgentState` field and no graph-topology change.
- All product and test code is generated by the OpenCode coding agent under the
  team's governance files; humans specify, review, and approve.
- The existing vendor rule "never derive a quarter" is kept.

### 2.3 Concerns

Look-ahead bias, circular verification by the coding agent, model
compliance with verified figures, and information loss in condensed context.

## 3. Attribute-driven design iterations

### Iteration 1 — correctness and traceability of derived figures

- **Goal:** QAS-1, QAS-5.
- **Element refined:** fundamentals analysis path (vendor → analyst → report).
- **Design concepts:** pure computation component; date-keyed period matching;
  explicit `n/a` instead of fallback values; provenance per value.
- **Instantiation:** `StatementParser`, `PeriodMatcher`,
  `DerivedMetricsCalculator`, `MetricsFormatter`; `MetricResult` contract
  (§5.2).
- **Analysis:** removes the wrong-period error class seen in the baseline
  (+68.6% vs +105.9%). Open issue: a tool alone depends on the model calling
  it, and downstream agents still read only model prose.

### Iteration 2 — delivery to every reader, and cost

- **Goal:** close the open issue of iteration 1; QAS-2.
- **Element refined:** report hand-off between analysts and downstream agents.
- **Design concepts:** code-owned appended block (model cannot edit it);
  single entry point for downstream report reads; always-on evidence budget;
  producer-written summary with deterministic validation and fallback.
- **Instantiation:** `VerifiedBlockAppender`; `report_brief_or_absent` with
  `BriefExtractor` and `FallbackCondenser`; marker contracts (§5.3).
- **Analysis:** estimated saving 29%-33% of input at a 2,000-character limit
  (evaluation logbook EL-13). New risk: briefs could drop data gaps or verified
  figures, which led to CB-INV-02 and CB-INV-03. Limit-triggered compression was
  rejected because the downstream prompts never reach its thresholds (EL-12).

### Iteration 3 — testability, robustness, and verifiability

- **Goal:** QAS-3, QAS-4, plus the concerns in §2.3.
- **Element refined:** module boundaries and the verification set-up.
- **Design concepts:** I/O isolated in one adapter; fail-open on brief errors;
  independent test oracle; deterministic fixture-based verification.
- **Instantiation:** `MetricsInputAdapter`; configurable `BriefPolicy`; reference values supplied
  by a team member in the agent task specification.
- **Analysis:** 9 of 11 acceptance criteria run as pure-function tests and 2 as
  offline tests with mocks. All remaining acceptance criteria are offline;
  no measured live cost or decision-quality benefit is claimed. Remaining risks are tracked in `risk-list.md` (R-01, R-04).

## 5. Components and contracts

### 5.1 Components

Paths are relative to the application package root (`tradingagents/`) and to
the course test layout.

| Component | Location (proposed) | Responsibility | Depends on |
|---|---|---|---|
| `MetricsInputAdapter` | `dataflows/derived_metrics.py` | Fetch statement text and the as-of close price | SEC vendor functions, verified market snapshot |
| `StatementParser` | same module | Turn statement text into typed period rows; reject malformed tables | standard library |
| `PeriodMatcher` | same module | Find comparison periods by end date; merge duplicates; mark ambiguity | standard library |
| `DerivedMetricsCalculator` | same module | Compute every metric in POL-DM-04 | parser, matcher |
| `MetricsFormatter` | same module | Render the table and the verified-metrics block | results only |
| `get_derived_metrics` | `agents/derived_metrics_tool.py` | LangChain tool with `InjectedState` ticker and trade date | adapter, calculator, formatter |
| `VerifiedBlockAppender` | `agents/analysts/fundamentals_analyst.py` | Append the block after the model's final reply | formatter |
| `BriefPolicy` | `agents/context.py` | Limit and markers | policy configuration |
| `BriefExtractor` | `agents/context.py` | Return a valid analyst-written brief | policy |
| `FallbackCondenser` | `agents/context.py` | Deterministic condensation (POL-CB-02) | policy |
| `report_brief_or_absent` | `agents/context.py` | Single entry for the five downstream agents | extractor, condenser |

### 5.2 Data contracts

```text
StatementRow
  period_end : date
  span       : "Q" | "6M" | "9M" | "FY"
  values     : {line_item: float | None}

MetricResult
  metric_id  : str
  period_end : date
  status     : "ok" | "approx" | "n/a"
  value      : float | None
  unit       : "pct" | "ratio" | "usd_m" | "usd_per_share" | "multiple"
  inputs     : [(label, period_end, value)]
  formula    : str
  reason     : str | None      # required when status is n/a
```

`span` comes from the column label: no suffix in a quarterly table is `Q`,
`(6 months)` is `6M`, `(9 months)` is `9M`, and every annual column is `FY`.

### 5.3 Text markers

```text
<!-- VERIFIED-METRICS v1 as_of=YYYY-MM-DD source=sec_edgar -->
| metric | period end | value | computed from |
...
<!-- /VERIFIED-METRICS -->

<!-- DOWNSTREAM-BRIEF v1 -->
- Stance:
- Key figures:
- Key levels / triggers:
- Data gaps:
<!-- /DOWNSTREAM-BRIEF -->
```

HTML comments do not render in Markdown viewers. The version tag lets a later
format change be detected.

## 6. Derived-metric rules

1. **Match by date, not position.** Year-ago: same span, end date 355-380 days
   earlier. Prior quarter: span `Q`, 80-100 days earlier.
2. **Duplicates.** End dates within 7 days with equal values are one period;
   unequal values make the metric `n/a` (ambiguous).
3. **No derived periods.** A quarter is never computed by subtracting filed
   periods. Fourth-quarter comparisons are `n/a`.
4. **TTM.** Latest FY + current-year quarters - their year-ago quarters, all
   filed figures. TTM EPS is `approx`.
5. **Cash flow on its reported span.** FCF = operating cash flow - capital
   expenditure on the filed span, compared with the same span a year earlier.
6. **As-of discipline.** Filings and prices on or before the analysis date only.
7. **Two P/E rows.** `pe_ttm` and `pe_fy` are always reported separately.

## 7. Brief rules

1. A report shorter than the limit passes unchanged.
2. A valid `DOWNSTREAM-BRIEF` block within the limit is used.
3. Otherwise `FallbackCondenser` builds the brief (POL-CB-02).
4. A `VERIFIED-METRICS` block is copied verbatim and not counted in the limit.

## 8. Failure behavior

| Condition | Behavior | User-visible effect |
|---|---|---|
| Ticker not in SEC EDGAR, or crypto | Not-supported message; no block | Report notes verified metrics are unavailable |
| Vendor error or timeout | Unavailable message with the error class | Same; analysis continues |
| Malformed statement table | Affected metrics `n/a`, reason `unparseable table` | `n/a` rows |
| No unambiguous comparison period | Metric `n/a` with reason | `n/a` row |
| Price unavailable | Valuation rows `n/a` | `n/a` rows |
| Brief missing, malformed, or oversized | Fallback condensation | Condensed report marked `[condensed]` |
| Exception in brief handling | Full report; warning logged | Baseline behavior for that call |

The last row fails open. Losing the saving on one call is safer than sending a
downstream agent an empty or truncated report.

## 9. Dependency direction and structural constraints

- The calculator, parser, matcher, and formatter import only the standard
  library and perform no network, file, model, or environment access.
- `MetricsInputAdapter` is the only component performing I/O.
- Brief functions in `context.py` depend only on the standard library and the
  policy constants.
- Neither change imports graph, CLI, memory, or report-writer modules.

These rules are stated as structural constraints for the coding agent and are
checked by an import-audit test in `test/offline`, intended as a blocking CI
gate.

## 11. AI context impact

Analyst reports are L3 evidence in the team's context-layer model. CR-01 is an
always-on policy for that layer in five downstream calls; it bounds each report
before any limit-triggered compression would apply. L0 safety constraints, L1
run identity, L2 role instructions, and L5 output contracts are unchanged.
Data-gap statements, which inform L1 coverage awareness, are always kept.

FR-01 adds one tool to the fundamentals analyst and one instruction to six
prompts: quote verified metrics and do not recompute them. Prompt changes are
versioned in the team's `prompts/` files.

## 13. Performance

Tables have at most about 80 columns; expected compute time is well under
50 ms per call. SEC data is already cached by the vendor for 24 hours, so the
tool adds no external requests beyond those of the statement tools. Brief
extraction is a linear scan of each report.

## 14. Change policy

Changes to period-matching windows, metric formulas, marker formats, the brief
limit, or the fallback order require updates to D1, ADR-003, the invariants,
the trace matrix, the option ledger, and tests, plus human review before merge.
