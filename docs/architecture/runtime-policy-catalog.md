## 1. Scope and vocabulary

The `RP-*` identifiers are document-locality labels. They are not requirements, states, or new acceptance criteria.

Three outcome dimensions remain separate:

| Dimension | Values | Meaning |
|---|---|---|
| Formal business result | `gate_status` `passed` / `blocked` / `error`; `final_rating`; `final_trade_decision`; top-level `reasons` | SB-01 output. REVIEW is a final rating, not a run failure. |
| Analysis control flow | Existing normal return or execution/save exception | No new persisted completed/failed state machine. A valid business REVIEW may return normally. |
| Artifact persistence | `not_requested` / `succeeded` / `failed` | Existing report, final-state or new-memory save outcome; no new persistence protocol. |
| External control flow | Existing return, exception, CLI error display/exit | Existing entry behavior, not a new status. |

A business REVIEW may return normally; formal-result contract failure follows the existing execution-error path. State, memory and requested-report failures retain original exception/display behavior without a new persisted run status.

No policy below adds a production timeout, retry, circuit breaker, global exception router, or persistent incident record. Existing vendor fallback/retry and model fallback behavior remains unchanged.

## 3. Primary-error priority and partial success

1. Only SB-01 generates formal business fields; no policy recomputes them.
2. Primary execution/save errors win over cleanup failures. Acquiring scopes release resources once and restore context binding.
3. Preserve existing state/report/new-memory failure behavior; files actually saved remain. Declined/no-op saves are not failures.
4. Independent saves consume passed state and create no new scope. Interruption implies no recovery or completion guarantee.
5. No current precise statistics, manifest, history monitor or new persisted status exists. Their archived policies apply only to future activation.
6. Retain data-observation conservative failure handling, exact risk decisions, missing-formal-result contract failures and safe supported credential diagnostics.

## 3. Primary-error priority and partial success

1. **Business result is independent.** No runtime policy recomputes, rewrites, or parses a substitute formal result. A business REVIEW is produced only by SB-01; a missing/invalid formal result is an execution contract failure.
2. **Primary execution/save error wins.** A cleanup error must not replace an existing analysis, final-state, memory, or requested-report error.
3. **No primary error, cleanup error:** follow the existing error style and do not record `completed`.
4. **Manifest is warning-only.** A manifest failure does not change the run outcome, formal result, return value, or original error, and does not force a non-zero CLI exit.
5. **Path-specific saves remain distinct.** Final-state, new-memory, and requested-report failures can make the run `failed`; memory disabled/same-day no-op and a declined report are not failures.
6. **Partial success is honest.** A confirmed Markdown report may remain after an HTML failure; a saved final state may remain after a memory failure; no successful artifact is deleted or rolled back solely because a later artifact failed.
7. **Independent save does not reopen the run.** Post-run `save_reports()` keeps its own failure behavior and leaves the completed run manifest unchanged.
8. **Interruption is not recovery.** A running/missing manifest, partial report, or absent memory record is not automatically repaired or treated as a completed result.
9. **No runtime consistency scanner.** Formal writer uniqueness, absence of `RunContext` in state/checkpoint, absence of model/data calls in FR-04/SB-01, and credential-summary shape are verified by planned static/offline checks, not by a production monitor.
10. **Propagation is pending.** The stats-handler reach through analyst subgraphs, parallel nodes, structured-output runnables, and graph-internal reflection is not a confirmed runtime guarantee until OQ-16 is resolved; the design fallback is local explicit execution-config handoff, not a global router.
