## 4. Coverage and boundaries

1. **Requirement coverage.** The overview contains all 13 current requirements. The active count is 9, and the deferred count is 4. No deferred requirement is assigned a current component, test task, interface, or monitoring point.
2. **FC coverage.** The active FC table contains all 40 active FCs: FR-01 5, FR-02 5, FR-03 5, FR-04 5, FR-05 5, SB-01 5, INV-01 3, SR-01 4, SR-02 3. The 15 deferred FCs remain future conditions and are not activated.
3. **No duplicate acceptance.** INV-01-FC01 may reuse the SB-01-FC05 output evidence; SR-02-FC03 may reuse FR-02/FR-05 path evidence. This avoids creating a second acceptance regime for the same behavior.
4. **No invented evidence.** No test function, test output, measurement, approval, report, or runtime observation is claimed. Planned `T-*` identifiers are descriptive only.
5. **Runtime monitoring.** Monitoring uses only existing/proposed design observables: manifest/manifest warnings, availability summary and report region, risk result, SB-01 formal fields, history read/list errors, and existing safe warnings. No periodic scan, alert backend, metrics service, trace database, audit ledger, or new warning file is added.
6. **No independent monitor cases.** FR-01 has no reuse-hit metric; INV-01 has no continuous cross-output equality monitor; FR-04/SB-01 determinism is verified offline; stats propagation is pending; deferred requirements have no current monitoring. In those cases the deterministic execution boundary plus the planned offline evidence is the stated verification method.
7. **Deferred boundary.** Context budgets, compression thresholds, and compressed-constraint reinjection remain deferred by ADR 001 D-10c and are absent from this matrix's implementation, acceptance, and monitoring columns. FR-06, FR-07, PR-01, and CR-01 remain deferred.
8. **Open verification impact.** OQ-16 affects FR-02-FC03/FC05 and IR-15; OQ-12 affects FR-03-FC01; OQ-13 affects FR-01-FC05 and FR-03-FC05; OQ-15 affects FR-03-FC04/FC05 and IR-10/IR-13. These are evidence gaps, not new requirements or new architecture decisions.
