Status: **personal draft / pending team review**
Implementation status: **design only; no permissions are enforced by this file**

Enforcement belongs in `.opencode/permissions.jsonc`, `.opencode/rules.md`,
CI, and branch protection (D3/D4). This document states the intended rules.

## Runtime AI (the trading agents)

The fundamentals analyst may call `get_derived_metrics`. The tool takes the
ticker and trade date from graph state, so the model cannot request another
instrument or a later date.

Runtime AI may not:

- write, edit, or remove the verified-metrics block — code appends it after the
  model's final reply;
- change metric formulas, period-matching windows, or rounding;
- choose the vendor used for derived metrics;
- change the brief size limit;
- decide which data-gap statements are kept in a brief;
- read files, environment variables, credentials, or arbitrary URLs through
  either feature.

A brief written by the model is advisory text. Code checks its size and
structure, and code alone decides whether it is used. Text in a report that
imitates a verified-metrics marker is ordinary report content; only the block
appended by code is treated as verified.

## Coding agent (OpenCode)

All product and test code for FR-01 and CR-01 is generated by OpenCode.
Humans do not edit generated code; a defect is corrected by a new, recorded
instruction to the agent.

| Session role | Allowed writes | Allowed reads | Explicitly denied |
|---|---|---|---|
| Builder | Package files listed in the trace matrix for FR-01 / CR-01 | Approved D1/D2, package source, recorded fixtures | Requirements, approved tests, fixtures' reference values, baseline evidence, secrets, Git history |
| Test author | `test/offline/**`, `test/live/**` for FR-01 / CR-01 | Requirements, architecture, fixtures, reference values supplied in the task specification | Product code; inventing reference values; changing a reference value without human instruction |
| Reviewer | None | Repository, diff, test output | All writes |

Rules that apply to every session:

- Expected values in tests come only from the reference values a team member
  writes into the task specification, each with its source (earnings release
  or hand calculation). The agent must not derive expected values by running
  the code under test.
- No session reads or prints the course endpoint key.
- No session runs live experiments; a human starts them.
- No commit, push, merge, reset, deletion, or dependency installation without
  explicit human approval in the session.

The exact allowlist is fixed in D3 before coding begins.

credentials, `.env`, runtime state, or another member's requirements.
