## 2. Confirmed necessity-target contract

**First eligible effective request fixes the target; the last accepted matching update determines its current result.**

| Necessary item | Confirmed target |
|---|---|
| Stock-price series | Current object and the first eligible request's effective start/end after existing date handling |
| Verified snapshot | Current object and analysis date; earlier-date requests cannot substitute. Utility lookback is not a necessity dimension; actual price rows may be earlier trading days |
| Income statement, balance sheet, cash flow | Each item independently binds the first eligible request's effective date/frequency for the current object, following existing interface/default semantics |
| Global news | First eligible request at the analysis date, with explicit effective lookback/limit or existing configuration defaults when omitted |
| Reddit | Current object and the existing sentiment-prefetch window/community parameters |

- Resolve existing parameters/dates/defaults before binding, and bind before fetch. Eligibility is independent of eventual success. Existing rejected parameters do not bind; no new rejection rule, CLI input, configuration key or forced frequency is introduced.
- Concurrent eligible requests use the registry lock; the first to acquire it binds. Release the lock before fetch. Binding is not a completed observation and consumes no completion sequence.
- Never switch a bound target during that analysis, including after failure, no-data or withheld results. A previously unbound item may bind on its first eligible later request. Snapshot generation does not bind targets.
- Retain other-query observations separately, but do not substitute another window/date/frequency because it succeeds. Match the target first, then use the last accepted matching observation or query-level failure mark; matching success may replace failure and vice versa.
- With neither a matching completed observation nor a matching mark, the applicable item is `not_attempted`; an in-flight request is not described as never started. A matching failure mark keeps its existing `unavailable` projection.
- Bindings are private run-local state, read consistently with accepted updates. They add no summary field, persistence, history, extra query/retry or FR-01 prerequisite. The existing seven-item list and supplementary-data distinction remain unchanged.
