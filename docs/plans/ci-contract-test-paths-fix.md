## 2. Observed symptom and root cause

- PR #7 CI run `44921168528` reported in `contract-tests`:

  `contract test does not exist:` followed by a path whose final component was
  the visual placeholder, not the real Round 1 risk test file.

- The approved Round 1 specification contained both:
  - the real test path; and
  - a placeholder used only to explain the extraction rule.
- `CONTRACT_TEST_PATTERN` in `scripts/ci_checks.py` allows `.` inside the path
  character class, so the placeholder was extracted as if it were a real path.
- `plan_test_paths()` returned every match, including the placeholder.
- `contract_test_plan()` then checked every returned path with
  `resolve_project_file()`. The placeholder did not exist, so the gate failed.
- The root cause is extraction of the explanatory placeholder, not a missing
  real test file and not a path-permission failure.

This specification deliberately does not write the placeholder as a contiguous
path token. It is described as three ASCII periods followed by the letters
`py`, with `test/offline/` as the directory prefix. The implementation tests
construct it from components so that this specification commit does not
re-trigger the same extraction defect.

## 4. Proposed minimal implementation

Keep `CONTRACT_TEST_PATTERN` unchanged and keep `contract_test_plan()`'s
existence checks unchanged.

Add one small predicate and filter only the exact observed placeholder at the
extraction boundary:

```python
def _is_ellipsis_placeholder(path: str) -> bool:
    return path.rsplit("/", 1)[-1] == "." * 3 + "py"


def plan_test_paths(plan_text: str) -> list[str]:
    return sorted(
        {
            path
            for path in CONTRACT_TEST_PATTERN.findall(plan_text)
            if not _is_ellipsis_placeholder(path)
        }
    )
```

Behavioral consequences:

- The exact placeholder whose final component is three ASCII periods plus
  `py` is ignored.
- Real paths are still extracted, sorted, and de-duplicated by the existing
  `sorted(set(...))` behavior.
- Every remaining path is still passed to `resolve_project_file()`, so a real
  but missing test file still fails with `contract test does not exist`.
- A specification containing only the placeholder produces an empty path list
  and therefore fails through the existing "contains no test/offline or
  test/live test paths" check.
- The filter is based on the exact placeholder basename, not on `Path.exists()`
  and not on a general "ignore missing files" rule.
- Approved-version reading, changed-code-path mention checks, collection,
  JUnit validation, and execution rules remain unchanged.

No `type: ignore`, new dependency, global path filter, or test-count change is
introduced.

## 5. Test specification

Add the following tests to `test/offline/test_ci_gates.py`, using the existing
`ci_checks`, `_repo`, `tmp_path`, and pytest style. Do not add a dependency or
new framework.

The tests construct the placeholder from components rather than embedding a
contiguous extractable path token. Expected values below are written
independently; they are not generated by calling `plan_test_paths()` or
`contract_test_plan()`.

| ID | Test name | Input | Independent expected result | Failure condition |
|---|---|---|---|---|
| T1 | `test_plan_test_paths_ignores_ellipsis_placeholder` | Specification text containing the real path `test/offline/test_ci_gates.py` and the placeholder built as `test/offline/` + three periods + `py`. | `plan_test_paths(text) == ["test/offline/test_ci_gates.py"]`. | The placeholder is returned, the real path is absent, or a duplicate appears. |
| T2 | `test_plan_test_paths_extracts_and_deduplicates_real_test` | The same real path repeated three times with backticks/separators, plus the placeholder. | Exactly `["test/offline/test_ci_gates.py"]`. | Multiple entries are returned, the placeholder appears, or the real path is missing. |
| T3 | `test_contract_plan_rejects_missing_non_placeholder_test` | A temporary spec file naming changed code `scripts/ci_checks.py` and an independently constructed `missing_test_path` (`test/offline/` + `missing_contract` + `.py`); the test file is not created. | `errors` is non-empty and includes `contract test does not exist` with `missing_test_path`; `test_paths == [missing_test_path]`, a one-element list containing the constructed path, not a bare path string. `missing_test_path` must be built from independent inputs and must not be generated by `plan_test_paths()` or any other function under test. | No error; the missing path is filtered out because it does not exist; or `test_paths` is a bare string or omits the constructed path. |
| T4 | `test_contract_plan_rejects_placeholder_only_specification` | A temporary spec file naming changed code `scripts/ci_checks.py` and only the placeholder, with no real test path. | `plan_test_paths(spec_text) == []`; `contract_test_plan()` returns non-empty errors including `contains no test/offline or test/live test paths`; `test_paths == []`. | The plan returns success or retains the placeholder as a test path. |
| T5 | `test_contract_plan_selects_real_test_when_spec_also_has_placeholder` | A temporary Git repository with a committed spec naming `scripts/ci_checks.py`, the real path `test/offline/test_ci_gates.py`, and the placeholder; the real test file exists with minimal content; call `contract_test_plan(..., spec_text=None)`. | `errors == []`; `test_paths == ["test/offline/test_ci_gates.py"]`. | A placeholder error occurs or the real path is not selected. |
| T6 | `test_contract_plan_fails_when_real_test_file_missing` | The same committed-spec setup as T5, but without creating the real test file. | `errors` is non-empty and includes `contract test does not exist` with `test/offline/test_ci_gates.py`; `test_paths == ["test/offline/test_ci_gates.py"]`; the placeholder is not retained. | The plan succeeds, or the real missing path is hidden by the filter. |

### 5.1 Test setup notes

- T1 and T2 are direct unit tests of `plan_test_paths()`.
- T3 and T4 use a temporary specification file plus `spec_text=` so that the
  path-existence checks are isolated from Git commit setup.
- T3 constructs `missing_test_path` from literal components before calling the
  code under test, so the expected `test_paths == [missing_test_path]` list does
  not depend on `plan_test_paths()` or `contract_test_plan()` output.
- T5 and T6 use the existing `_repo()` helper, commit the synthetic
  specification, and pass `spec_text=None` so the approved-commit reading path
  is exercised. The synthetic test file is created under the temporary repo,
  not in the real repository.
- T5 and T6 use minimal synthetic test-file content; they do not alter the real
  `test/offline/test_ci_gates.py`.
- No test creates a file with the placeholder basename.
- Existing tests for multiple real paths, missing approval fields, wrong code
  paths, governance selection, collection, and JUnit execution remain
  unchanged.

### 5.2 Pre-fix and post-fix expectations

- On the current implementation, T1, T2, T4, T5, and T6 should fail for the
  placeholder-extraction reason; T3 should pass before and after because it
  guards against existence-based over-filtering.
- After the fix, all six tests must pass.
- Failures must come from the intended assertions, not import errors, fixture
  errors, or Git setup errors.
